1. MODEL 1: 2D CAMERA VISION YOLO OBJECT DETECTOR
====================================================================================================

1.1 Overview & Objective
-------------------------
Model 1 handles real-time 2D optical visual perception from forward-facing camera frames.
It is explicitly customized to recognize unstructured Indian traffic scenarios and road anomalies
where lane discipline is absent and edge obstacles frequently occur.

1.2 Target Object Classes (7 Classes)
-------------------------------------
  Class ID 0: auto_rickshaw  - Three-wheeled passenger vehicle
  Class ID 1: cow_cattle     - Stray animals / cattle crossing roads
  Class ID 2: pedestrian     - Walking or darting pedestrians
  Class ID 3: two_wheeler    - Motorcycles, scooters, and bicycles
  Class ID 4: pothole        - Road surface craters and road defects
  Class ID 5: truck_bus      - Heavy commercial vehicles and buses
  Class ID 6: car            - Light motor vehicles (sedans, hatchbacks, SUVs)

1.3 Architecture & Design
-------------------------
- Architecture: CSPDarknet Backbone + Feature Pyramid Network (FPN / PANet) + Decoupled Detection Head.
- Backbone: Cross-Stage Partial Darknet (CSPDarknet) extracts multi-scale visual features while 
  reducing redundant gradient computations.
- Neck: PANet (Path Aggregation Network) fuses low-level spatial detail (crucial for potholes & pedestrians) 
  with high-level semantic features (for large trucks and buses).
- Head: Decoupled anchor-based/anchor-free 2D bounding box regression and multi-class classification heads.

1.4 Algorithmic Mechanism
-------------------------
- Algorithm: Single-stage 2D Object Detection (YOLO Paradigm).
- Feature Extraction: The normalized RGB frame is passed through convolutional downsampling layers.
- Bounding Box Representation: Each box is parameterized as [x_center, y_center, width, height] 
  normalized to [0, 1].
- Non-Maximum Suppression (NMS): Redundant overlapping bounding boxes are suppressed using 
  Intersection over Union (IoU) thresholding (typical IoU threshold: 0.45 - 0.50).
- Confidence Filtering: Detections with objectness confidence score < 0.40 are rejected.

1.5 Mathematical Loss Formulation
---------------------------------
  Total_Loss = λ_box * L_box + λ_cls * L_cls + λ_conf * L_conf
  - Bounding Box Regression Loss (L_box): CIoU (Complete IoU) / Smooth L1 Loss measuring 
    overlap, centroid distance, and aspect ratio consistency.
  - Classification Loss (L_cls): Multi-class Binary Cross-Entropy (BCE) over 7 target classes.
  - Objectness Confidence Loss (L_conf): Binary Cross-Entropy (BCE) penalizing false positive 
    background detections and false negatives.

1.6 Input & Output Specifications
---------------------------------
- Input Tensor:  `camera_frame`
  - Shape:       [1, 3, 640, 640] (Batch=1, Channels=3 RGB, Height=640, Width=640)
  - Data Type:   Float32, normalized values in range [0.0, 1.0]
- Output Tensor: `detected_boxes`
  - Shape:       [1, 25, 12] (Batch=1, Top 25 Candidate Detections, 12 Attributes)
  - Channels (12 dims):
    [x_center, y_center, width, height, c0, c1, c2, c3, c4, c5, c6, confidence]
    where c0..c6 are the class probability scores for the 7 categories.

1.7 Export & Deployment
-----------------------
- Checkpoint: `best_model1_yolo.pth` (PyTorch)
- Export Format: `model1_camera_yolo.onnx` (ONNX Opsset 14+)
- MATLAB Import: `importONNXNetwork('model1_camera_yolo.onnx')` for real-time camera inference.


====================================================================================================
2. MODEL 2: 3D LIDAR OBJECT DETECTOR (POINTPILLARS / POINTNET ARCHITECTURE)
====================================================================================================

2.1 Overview & Objective
-------------------------
Model 2 performs 3D spatial object detection and volumetric bounding box estimation directly from 
sparse, unstructured 32-beam LiDAR point clouds (trained on nuScenes dataset). It computes exact 
3D metric coordinates [X, Y, Z], physical dimensions, and orientation angles regardless of lighting 
or weather conditions.

2.2 Target Object Classes (3 Classes)
-------------------------------------
  Class ID 0: Car
  Class ID 1: Pedestrian
  Class ID 2: Cyclist / Motorcycle / Dynamic Obstacle

2.3 Architecture & Design
-------------------------
- Architecture: Point-based 3D Spatial Feature Net & Multi-Object Regressor (PointNet / PointPillars concept).
- PointCloudEncoder (PointNet-style):
  - Convolutions: 1D Convolutions with Batch Normalization and ReLU activations:
    Conv1D(4 -> 64) -> Conv1D(64 -> 128) -> Conv1D(128 -> 256).
  - Symmetry Function: Channel-wise Global Max Pooling over all points (N = 16,384) to yield a 
    permutation-invariant 256-dimensional global scene embedding.
- Dense Aggregation & Proposal Decoder:
  - Multi-Layer Perceptron (MLP): Linear(256 -> 512) -> BN -> ReLU -> Dropout(0.1) -> Linear(512 -> 512) -> BN -> ReLU.
- Decoupled Multi-Task Regression Heads:
  1. 3D Box Regressor: Linear(512 -> K * 8) predicting 8 geometric values per box proposal:
     [X, Y, Z, Width, Length, Height, sin(yaw), cos(yaw)].
  2. Class Logits Head: Linear(512 -> K * 3) predicting class distribution scores.
  3. Objectness / Confidence Head: Linear(512 -> K * 1) followed by Sigmoid activation.

2.4 Algorithmic Mechanism
-------------------------
- Permutation Invariance: Raw LiDAR point clouds are unordered. By applying shared 1D conv weights across 
  all points followed by a global symmetric reduction (Max-Pooling), the network is robust to point order.
- Continuous Yaw Angle Encoding: Rather than predicting raw yaw angle θ directly (which suffers from 
  discontinuities at ±π), the network predicts [sin(θ), cos(θ)]. The predicted orientation is recovered 
  via θ = atan2(sin(θ), cos(θ)), guaranteeing smooth angle estimation.
- Masked Multi-Task Backpropagation: Box regression and classification losses are computed ONLY on valid 
  ground-truth objects using target valid masks (`target_valid > 0.5`).

2.5 Mathematical Loss Formulation
---------------------------------
  Total_Loss = 2.0 * L_box + 1.0 * L_cls + 1.5 * L_conf
  - 3D Box Loss (L_box): Smooth L1 Loss on ground-truth matched bounding boxes:
      Smooth_L1(x) = 0.5 * x^2           if |x| < 1
                     |x| - 0.5           otherwise
  - Classification Loss (L_cls): Multi-Class Cross-Entropy Loss over the 3 classes.
  - Objectness / Confidence Loss (L_conf): Binary Cross-Entropy (BCE) comparing predicted confidence 
    against object presence validity.

2.6 Input & Output Specifications
---------------------------------
- Input Tensor:  `points`
  - Shape:       [Batch, 16384, 4]
  - Channels (4 dims): [X, Y, Z, Intensity] (in LiDAR sensor frame, metric units)
- Output Tensor: `predicted_boxes`
  - Shape:       [Batch, 20, 12] (20 candidate 3D boxes)
  - Channels (12 dims):
    [X, Y, Z, Width, Length, Height, sin(yaw), cos(yaw), cls_0, cls_1, cls_2, confidence]

2.7 Export & Deployment
-----------------------
- Checkpoint: `best_model2_lidar.pth` (PyTorch)
- Export Format: `model2_lidar.onnx` (ONNX format)

3. MODEL 3: MULTI-AGENT MOTION & TRAJECTORY PREDICTOR
====================================================================================================

3.1 Overview & Objective
-------------------------
Model 3 is a temporal forecasting network that observes the past motion of dynamic traffic participants 
(animals, pedestrians, two-wheelers, cars) and predicts their future coordinates. 
This enables the autonomous driving system to transition from purely reactive obstacle avoidance to 
predictive, risk-aware path planning.

3.2 Architecture & Design
-------------------------
- Architecture: Temporal 1D Convolutional Neural Network (Temporal CNN) + Multi-Horizon Dense Decoder.
- Translational Invariance Pre-processor:
  - Computes relative offsets with respect to the agent's latest known coordinate:
    rel_past = past_traj - last_pos
    This ensures predictions are invariant to the agent's global position in the world.
- Temporal Feature Extractor:
  - 1D Temporal Convolutions applied along the time dimension:
    Conv1D(in_channels=2, out_channels=64, kernel=3, padding=1) -> BN -> ReLU
    Conv1D(in_channels=64, out_channels=128, kernel=3, padding=1) -> BN -> ReLU
  - Captures velocity, acceleration, and curvature changes across observation timesteps.
- Trajectory Decoder:
  - Flattened temporal representation (hidden_dim * past_len = 128 * 8 = 1024 features)
  - Dense layers: Linear(1024 -> 256) -> ReLU -> Dropout(0.1) -> Linear(256 -> 256) -> ReLU -> Linear(256 -> 24)
  - Outputs 24 values representing future relative (ΔX, ΔY) across 12 future timesteps.
- Absolute Path Reconstructor:
  - Adds the base position back to relative predictions:
    future_traj = last_pos + predicted_relative_displacements

3.3 Algorithmic Mechanism
-------------------------
- Temporal Sequence Modeling: Past 8 waypoints sampled at 5 Hz (representing 1.6 seconds of history) 
  are fed into temporal convolutional filters.
- Horizon Forecasting: Forecasts 12 future waypoints at 5 Hz (representing the next 2.4 seconds).
- Indian Non-Lane Traffic Modeling: Trained on complex nonlinear trajectories representing sudden 
  cattle crossings, pedestrian jaywalking, aggressive two-wheeler cutting, and vehicle lane deviations.

3.4 Mathematical Loss Formulation
---------------------------------
The model optimizes a multi-objective displacement loss:
  Total_Loss = ADE + 0.5 * FDE

  1. Average Displacement Error (ADE):
     Measures the mean Euclidean distance between predicted waypoints and ground truth across all timesteps:
     ADE = (1 / T) * Σ_{t=1}^{T} || (x_hat_t, y_hat_t) - (x_t, y_t) ||_2

  2. Final Displacement Error (FDE):
     Measures the terminal position error at the final prediction horizon (t = 2.4s):
     FDE = || (x_hat_T, y_hat_T) - (x_T, y_T) ||_2

3.5 Input & Output Specifications
---------------------------------
- Input Tensor:  `past_trajectory`
  - Shape:       [Batch, 8, 2] (8 timesteps of (X, Y) historical positions over past 1.6s)
- Output Tensor: `future_trajectory`
  - Shape:       [Batch, 12, 2] (12 timesteps of (X, Y) predicted positions over next 2.4s)

3.6 Export & Deployment
-----------------------
- Checkpoint: `best_model3_trajectory.pth` (PyTorch)
- Export Format: `model3_trajectory_predictor.onnx`

4. MULTI-SENSOR PERCEPTION & PREDICTION INTEGRATION PIPELINE
====================================================================================================

The three models form a unified perception and prediction pipeline for offline autonomous driving:

+-------------------+       +--------------------+       +--------------------+
|   Camera Frame    |       |  LiDAR Point Cloud |       | Past Trajectories  |
|  [1, 3, 640, 640] |       |  [Batch, 16384, 4] |       |    [Batch, 8, 2]   |
+---------+---------+       +---------+----------+       +---------+----------+
          |                           |                            |
          v                           v                            v
    +-----------+               +-----------+                +-----------+
    |  MODEL 1  |               |  MODEL 2  |                |  MODEL 3  |
    | Camera    |               | LiDAR 3D  |                | Motion    |
    | YOLO Det. |               | PointNet  |                | Predictor |
    +-----+-----+               +-----+-----+                +-----+-----+
          | 2D Boxes & Classes        | 3D Bounding Boxes          | Future (X,Y)
          |                           | [X,Y,Z,W,L,H,Yaw]          | Waypoints (2.4s)
          +------------+--------------+                            |
                       |                                           |
                       v                                           v
         +---------------------------+               +--------------------------+
         | Multi-Sensor Kalman Fusion|-------------->| Risk & Collision Engine  |
         | (Spatial Calibration &    | Tracked State | (TTC, Distance, Relative |
         | Object Association)       | & Velocities  | Speed Estimation)        |
         +---------------------------+               +-------------+------------+
                                                                   |
                                                                   v
                                                     +--------------------------+
                                                     | Safe Local Path Planner  |
                                                     | & Vehicle Control (MPC)  |
                                                     +--------------------------+

Key Fusion Metrics:
1. Spatial Calibration: Extrinsic matrix maps Camera 2D pixels to LiDAR 3D metric coordinates.
2. Kalman Filter Tracking: Continuously tracks obstacles across frames and computes relative velocities.
3. Time-to-Collision (TTC):
     TTC = (Relative Distance) / (Relative Velocity)
     Triggers adaptive steering, speed de-escalation, or emergency braking if TTC < safe threshold.
